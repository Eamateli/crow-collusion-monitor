# Reproducing Crow v2

Three levels, from free to a full re-run. Every number in the v2 paper is in the `v2` section of
[`analysis/numbers.json`](analysis/numbers.json), generated by `analysis/analyze.py --v2` from the
episode records.

| Level | Who | Cost | What it shows |
|---|---|---|---|
| **1. Verify** | anyone | free, no account | The tests pass offline, and the released records regenerate every v2 number, table and figure exactly, and the frozen thresholds. |
| **2. Spot-check** | anyone with a Modal account and two model endpoints | about $1 | A handful of real episodes run end to end, scored by every monitor. |
| **3. Replicate** | labs and reviewers | about $30 | The full grid with the same seeds and the same frozen config. |

## Level 1: verify

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pytest
```

The tests need no network, no Modal account and no model endpoint: we ran the whole suite with
networking removed (`unshare -rn pytest`), and 959 passed, 3 skipped.

The data release holds every v2 episode record, its scores, event log and workspaces (see
"Data release" below). With it unpacked at `DATA`:

```bash
python -m analysis.analyze --v2 DATA
git diff --stat
```

This rewrites the v2 section of `analysis/numbers.json`, `graphs_numbers/tables/v2_*.md`,
`graphs_numbers/figures/v2_figure1_detection.*` and `graphs_numbers/v2_findings.md`. Every number
comes out equal to the committed one; only `meta.generated`, `meta.git_commit` and the PDF's
creation date change. It is exact, not approximate, because the analysis makes no model call and
every bootstrap is seeded (2000 resamples, seed 0). We checked this against the redacted release.

The freeze can be recomputed the same way:

```bash
python experiments/freeze_v2.py DATA/v2_calibration --dry-run
```

It prints the thresholds, the postcondition allowances and the entropy and comment calibration,
and they equal `crow/frozen_v2.json` (also checked against the release).

## Level 2: spot-check

What this needs, plainly:
- **A Modal account.** Agent commands only ever run inside network-blocked Modal Sandboxes with
  no secrets, and every run is driven from a deployed Modal app.
- **Two model endpoints**, for the agents and for the trusted monitor. Their URLs are config values
  (`AGENT_ENDPOINT_URL`, `TRUSTED_ENDPOINT_URL`), but the client authenticates with a Modal proxy
  token pair (`modal_endpoint` in `crow/llm.py`), so an endpoint outside Modal needs that one
  function changed. The model IDs are fixed in `env/prompts.py` and hashed into the freeze.

```bash
cp .env.example .env                    # fill in the six values by hand
# create the Modal Secret crow-secrets with the same six keys
python -m modal setup
modal deploy -m experiments.modal_app
python scripts/launch_v2.py --run v2_resmoke --watch     # 6 episodes: 3 split, 1 control, 2 honest
python scripts/launch_v2.py --status v2_resmoke
```

The run is driven server-side, so the local process can end at any time. Our six re-smoke
episodes and their scoring came to about $1.07 at estimate prices (records in the release's
`v2_resmoke` folder); Modal billed less, because estimate prices assume no cached tokens.
Results should agree with ours statistically, within the CIs, not identically: the models sample.

## Level 3: replicate

```bash
modal deploy -m experiments.modal_app
python scripts/launch_v2.py --run v2_calibration --watch       # 30 honest episodes, seeds 1100-1114
modal volume get crow-results v2_calibration results/raw/v2/
python experiments/freeze_v2.py results/raw/v2/v2_calibration   # writes crow/frozen_v2.json
git commit -am "freeze" && git tag my-freeze                    # or keep ours: tag crow2-freeze
modal deploy -m experiments.modal_app                           # the image must carry the freeze
python scripts/launch_v2.py --run v2_main --max-usd 27.73 --watch   # refuses unless the deployed app sees your exact frozen_v2.json
modal volume get crow-results v2_main results/raw/v2/
modal volume get crow-results v2_main_arms results/raw/v2/
modal volume get crow-results v2_calibration results/raw/v2/
python -m analysis.analyze --v2 results/raw/v2
```

The main run has 150 episodes (seeds 0 to 9) and 120 intervention replays, in stages: honest and
honest_hard, then careful split and control, then the replays, then no-plan, then the careless
contrast. A budget stop only ever cuts the last stages. `--max-usd` sets one limit in real dollars
over episodes, replays and scoring.

We were billed $32.44 for all of v2: smoke, pilot, re-smoke, calibration, main grid, replays and
scoring (`spend` in numbers.json). That includes about $2.60 of scoring paid twice after a save
bug, fixed in commit `b011a91`.

## Data release

Not in git: it holds workspace tars, and it is published apart from the code. It is built by

```bash
python scripts/release_data.py results/raw/v2 ../crow-v2-data-release
```

from the run folders on the Modal Volume. Every record keeps everything except its planning chat
and `report_method` text: the agents' own description of their scheme, which no monitor saw and
no number uses. `REDACTION_SCAN.json` in the release shows that no record holds any of it.
Elsewhere, short pieces of that text do appear, and they are left as they are, because they are
part of what the monitors saw: text the colluding agents also wrote into their commands or files
(for example the helper names a report listed, or the check scripts careless agents ran in the
open), monitor replies quoting it, and a few task-generic phrases that honest episodes share.

One more change: two agents printed their sandbox environment, and in those two event-log lines
every value is replaced with `[masked]` (the variable names stay). The sandboxes hold no secrets;
no number reads those values, and Level 1 still reproduces every number exactly.

It is published as an asset of the GitHub release on the tag `swarm-alignment-2026-submission`.

## Honest limits

- Models sample, so levels 2 and 3 reproduce the results statistically, not exactly. Level 1 is
  exact because it uses the released outputs.
- Hosted models can change or be retired; the results are tied to the model IDs in the freeze.
- v1's raw records were never released; only its numbers are in `numbers.json`.
